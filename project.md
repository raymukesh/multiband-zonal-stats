# Project Context: Multiband Zonal Stats

This document is the durable technical handoff for continuing the project on a
different computer or in a new development session. Read it together with
`README.md` and `CHANGELOG.md`.

## Mission

Build a fast, dependable QGIS plugin that calculates zonal statistics for many
polygon or multipolygon features across multiband rasters and writes clean,
predictable CSV output. Performance is the primary design constraint.

The plugin must avoid the common slow pattern of reading the raster separately
for every polygon and every band. It should stay responsive, use bounded memory,
handle overlapping zones correctly, preserve useful band names, and serve both
continuous and categorical rasters from one shared read/mask engine.

## Current user workflow

The user can run the plugin from:

- the Raster menu and plugin toolbar;
- the custom graphical dialog;
- the Processing Toolbox (two separate algorithms);
- QGIS Model Builder or another Processing client.

The graphical dialog provides:

- raster and polygon layer selectors, with optional per-input CRS overrides
  (`Raster CRS` / `Zones CRS`) for layers whose declared CRS is missing or wrong;
- polygon ID and name field selectors;
- live validation of band expressions such as `all`, `1-8`, or `1,3,7`;
- an **Exclude values** field to drop specific pixel values (extra nodata),
  e.g. 0 for out-of-boundary in categorical rasters;
- an optional band-name **prefix** and **suffix** applied to output labels;
- two mode tabs — **Continuous raster** and **Categorical raster** — where the
  active tab is the analysis mode, each with its own statistics list and layout;
- output file selection;
- tile size, band chunk size, and all-touched advanced options;
- background progress, safe cancellation, and result opening;
- a right-side **About** panel summarising the plugin (name, version, author and
  a short how-to), read live from `metadata.txt`;
- a **Help** button that opens the bundled `help.html` in the default browser;
- a **Histogram…** button that previews a band's distribution (continuous bins
  or categorical class counts) in a QPainter popup, via `engine.raster_histogram`
  (whole raster, read decimated for speed; ignores the polygons).

## Analysis modes, statistics and output

Both modes share the same tiled read/mask path; only the per-zone accumulation
and the CSV layout differ.

### Continuous

Numeric statistics per polygon and band: valid pixel count, nodata pixel count,
minimum, maximum, sum, mean, and population standard deviation (divided by `n`,
matching QGIS). Two layouts:

- **Long** — one row per polygon and band:
  `fid,polygon_id,polygon_name,band_index,band_name,<selected stats>`
- **Wide** — one row per polygon; each band's stats become columns prefixed with
  that band's own (sanitised, unique) name, e.g. `ndvi_mean,ndvi_sum`.

### Categorical

Values are read as integer class codes (floating rasters are rounded). A raster
with more than `MAX_CATEGORICAL_CLASSES` (65,536) distinct values is rejected as
"looks continuous." Three layouts:

- **Summary** — one row per polygon and band: majority (most common class),
  minority (least common class), variety (distinct class count), plus valid and
  nodata counts. Majority/minority ties resolve to the lowest class code.
- **Class breakdown** — one row per polygon, band and class, with the class's
  pixel count and its fraction of the zone's valid pixels.
- **Class counts (wide)** — one row per polygon and band, with a `class_<code>`
  pixel-count column per class. Columns are the union of classes across all
  zones, so every row shares the same columns (absent classes are 0).

### Band names

Output labels come from raster band descriptions, falling back to `band_001`,
`band_002`, … when unnamed. The optional prefix/suffix wrap that label; the
raster's bands are never renamed. Wide-format headers are additionally
sanitised (lowercased, non-alphanumerics to underscores, collisions numbered)
via `utils.unique_header_names`, which — unlike `clean_column_name` — keeps a
leading digit so `2020_ndvi` stays as written.

Every row, in every layout, begins with a unique 1-based `fid` column assigned in
write order — the stable identity of that row (`engine._RowWriter`). The same
wrapper applies the optional `decimal_places` setting: when set (0–15), it fixes
the decimals of floating-point cells (stats, fraction) while leaving integers and
text untouched; `None` (the default, `-1` in the UI) keeps the full-precision
repr. CSV output is UTF-8 and is written to a temporary file before an atomic
rename, so cancellation or failure never publishes a partial result.

> Note: earlier releases (≤0.4.0) emitted per-zone `area`/`area_unit` columns and
> metric-area units. That was removed in 0.4.0 — area no longer forces a
> projected CRS, so geographic rasters run without an override.

## Performance architecture

The raster, not each polygon, is the unit of work:

1. The Processing algorithm validates inputs and copies each feature geometry.
2. Geometries are transformed once into the raster CRS.
3. An affine-aware tile index maps zone bounds to relevant raster tiles in
   approximately O(number of zones), avoiding a full polygon scan per tile.
4. The raster is read in bounded windows and selected bands are read in chunks.
5. Candidate polygons are rasterized into an in-memory integer label grid.
6. A shared generator (`engine._iter_masked_pixels`) yields the valid zone ids
   and values for each (window, group, band); continuous and categorical writers
   consume it, so the raster is read and each mask rasterized exactly once.
7. NumPy `bincount`, `minimum.at`, `maximum.at`, and `np.unique` update zone
   accumulators without Python loops over raster pixels. Standard deviation uses
   Chan's parallel variance merge for precision on large-magnitude rasters.
8. Finished band chunks are streamed to the CSV in stable band/zone order.

Peak memory is primarily controlled by `tile_size` and `band_chunk_size`
(defaults 1024 pixels and eight bands), plus a capped per-window mask cache.

### Multipart and overlapping zones

All parts of a multipart feature share one internal zone ID. Holes are retained.

A label raster can hold only one zone ID per pixel, so overlapping candidates
are greedily divided into passes whose bounding boxes do not overlap. Each pass
gets a separate label mask. This is conservative—it may create an unnecessary
extra pass when bounding boxes overlap but geometries do not—but it preserves
correct results for overlapping polygons. Touching bounds are also separated so
the all-touched option cannot lose a boundary pixel to label overwriting.

## Compatibility decisions

- `compat.py` resolves Qt5/Qt6 and QGIS 3/4 differences (scoped vs unscoped
  enums, `QAction` moving to QtGui, class-scoped enums relocated into `Qgis`),
  preferring the modern spelling and falling back to the legacy one.
- The Processing provider is registered even when QGIS loads the plugin without
  a desktop interface; GUI imports and actions are deferred for headless use.
- The algorithm provides its own translation helper because QGIS 4 no longer
  exposes the inherited `tr()` behavior used by older examples.
- The engine uses the GDAL/NumPy installations bundled with QGIS; the plugin has
  no separately downloaded runtime dependencies.
- Each background run receives copied geometry data and paths instead of using
  GUI widgets from a worker thread.

so run the suite with QGIS's bundled Python, for example:

```bash

    tests.test_utils tests.test_engine_helpers \
    tests.test_engine_integration tests.test_engine_categorical

python -m compileall -q .
```

`tests/test_utils.py` is pure Python and also runs under any interpreter.

Before a release, manually verify at least:

- a multiband raster with and without band descriptions, plus a prefix/suffix;
- polygon and multipolygon layers;
- overlapping zones and touching boundaries;
- holes, empty geometries, nodata, and zones outside the raster;
- a CRS transformation between the vector and raster, and a CRS override;
- pixel-centre and all-touched modes;
- cancellation without a partial final CSV;
- both modes: continuous long/wide, and categorical summary/breakdown/counts.

Build the installable package with:

```bash
python scripts/build_package.py
```

Update `metadata.txt` and add a `CHANGELOG.md` entry when bumping the version;
the package filename and file list are derived automatically from the tree.

## Known limitations

- Exact median and percentile statistics are not implemented because they need a
  different, more memory-intensive aggregation strategy.
- Geographic rasters report no metric area (area output was removed in 0.4.0);
  pixel counts are always available.
- Categorical mode assumes integer class codes; floating rasters are rounded, and
  a raster with too many distinct values is rejected rather than aggregated.
- One optimized background processing task is used; adaptive multi-worker
  execution has not been benchmarked or implemented.
- Invalid non-empty geometries are not automatically repaired.
- The engine targets GDAL-readable raster sources; provider-only QGIS raster
  sources are rejected with guidance to export to GeoTIFF first.
- There is no benchmark report yet against QGIS's standard zonal-statistics
  workflow on representative large datasets.

## Recommended roadmap

1. **Benchmark before further optimization.** Add repeatable synthetic and real
   dataset benchmarks measuring elapsed time, peak memory, raster tiles read,
   polygon count, and band count.
2. **Categorical enrichment.** Optional class-name lookup table and per-class
   area/percentage columns building on the existing class histogram.
3. **Adaptive memory planning.** Replace the fixed band-chunk default with a
   memory budget that considers tile dimensions, raster dtype, band count, and
   accumulator size.
4. **Geometry diagnostics.** Add optional repair, per-feature status, and clearer
   reporting for empty, invalid, outside-raster, and no-valid-pixel zones.
5. **Optional statistics.** Add variance and approximate/exact percentiles only
   when explicitly requested.
6. **Locale-friendly CSV.** Optional semicolon-delimited, comma-decimal output
   for spreadsheet locales that do not parse `.`-decimal numbers.
7. **Release automation.** Add CI for unit tests, QGIS 3/4 compatibility checks,
   package validation, and tagged ZIP releases.

## Non-negotiable design principles

- Never introduce a polygon × band loop that repeatedly rereads full raster
  areas.
- Never perform per-pixel calculations in Python when a GDAL or NumPy operation
  can do the same work.
- Preserve correctness for overlapping polygons, multipart features, holes, and
  per-band nodata.
- Keep memory bounded and make costly accuracy options explicit.
- Keep Processing and graphical runs on the same engine implementation.
- Keep output column names, row ordering, band names, and encoding deterministic.
- Do not publish a partially written CSV after cancellation or failure.
